# 前端自动恢复

画板 Worker 在 HTML 的入口模块之前注入 runtime-monitor.js 和本次发布标识。检测未捕获异常、未处理的 Promise 拒绝、脚本及样式加载失败、30 秒后仍未挂载；React 的 onUncaughtError 也接入报告。仅发送脱敏、截断后的消息和脚本位置。客户端不做周期 HTTP 轮询，只在错误发生及首次健康观察结束时报告。

控制 Worker 校验 Origin、发布 ID、当前线上版本和每 IP 频率，忽略旧版本。同一出错源码树只恢复一次，单个任务最多三次自动恢复。浏览器报告属于不可信数据，不具有发布或管理员权限；诊断以引用数据发送给 Jules。

管理员首次使用 mark_stable 登记已确认的稳定版本。之后，已完成的任务只有收到浏览器健康观察报告，且源码与线上版本一致时才更新稳定版本。健康观察不是完整的浏览器测试。

检测异常后，持久化恢复意图并暂停队列，阻止新的凭据领取。确认当前仍是出错版本后，通过 Cloudflare 将记录的稳定 Worker 版本部署为 100% 流量；校验健康树与实际版本 ID 后，向原 Jules 会话发送诊断和修复命令，恢复该任务的队列位置。修复仍须通过原有检查、发布和 PR 树核验。重复投递不会重复回退或重复发送指令。

回退或消息结果不确定时保持暂停，需管理员检查。回退只恢复 Worker 代码、资源和配置，不撤销数据库及外部副作用。尚未发生浏览器访问时无法发现浏览器运行错误；被捕获或仅 console.error 的错误不自动触发回退。无法追踪到原任务、存在其他占用任务或未登记稳定版本时，不猜测回退对象。
